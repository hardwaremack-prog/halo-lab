Why is the NPU usually at 0%?

The NPU is a low-power AI chip built for efficiency, not raw speed. Ollama, LM Studio and llama.cpp run models on the GPU, which is far faster for big models on this machine, so the NPU sits idle while you chat with them. That's normal.

To put the NPU to work, use one of the models in Model Library → Runs on the NPU with AMD's free FastFlowLM, or AMD Lemonade Server with a model marked NPU or Hybrid, and pick that engine at the top right. Hybrid models read your prompt on the NPU and write the answer on the GPU. Windows Studio Effects (camera blur, eye contact) and some Copilot+ features also use the NPU, and they'll show up here too.

Setup

Halo Lab works on its own: open it with the desktop icon and everything else happens here. Nothing to install by hand.

How it works

  1. The Halo Lab desktop icon starts a small background program (look for the orange ring near the clock). It opens this page, runs the CPU/GPU/NPU meters and manages the AI engine. Right-click the ring to quit.
  2. The first time, Chat offers to set up the AI engine: llama.cpp's official Vulkan build, which runs models on the Radeon 8060S.
  3. Models download from Hugging Face into the models folder above. When you chat with one, it loads into GPU memory by itself. Only one model is loaded at a time, and picking another swaps it automatically.

GPU memory

  1. The engine uses the memory set aside for the GPU plus shared memory, so on a 96 GB EVO-X2 it can use about 76–80 GB even with the default setting. Setup above and the Library show the real number for your PC.
  2. That's enough for every model in the Library, including gpt-oss 120B. You only need to change anything if a model shows Too big.
  3. If you do: AMD Software: Adrenalin Edition → Performance → Tuning → Variable Graphics Memory (also in the BIOS as the UMA frame buffer size), then restart. Leave Windows at least 16 GB.

Other engines (optional)

  1. Ollama: install from ollama.com/download, then pick Ollama at the top right. If the dot stays red, run Fix Ollama connection.bat once. Note: on Windows, Ollama may run this chip on the CPU only, which is much slower. Check the GPU meter while it answers.
  2. LM Studio: in the Developer tab, start the server and turn on Enable CORS. Download models in LM Studio's own Discover tab.
  3. FastFlowLM (runs models on the NPU): install flm-setup.msi from github.com/FastFlowLM/FastFlowLM/releases (it needs AMD's NPU driver 32.0.203.311 or newer). In PowerShell run a command from the Library's Runs on the NPU section, for example flm serve qwen3:8b, which downloads the model the first time. Then pick FastFlowLM (NPU) at the top right and chat. The NPU meter in the Hardware tab lights up while it answers.
  4. AMD Lemonade Server: AMD's app that can run models on the NPU (FastFlowLM inside) or in Hybrid mode (the NPU reads your prompt, the GPU writes the answer). Use its model manager, then pick AMD Lemonade at the top right.

Engine addresses

Hardware meters

The CPU, GPU and NPU meters read the same counters Task Manager uses. Seeing NPU activity needs Windows 11 24H2 or newer and AMD's NPU driver.

Speed tips for this chip

  1. MoE models fly here. Models like Qwen3 30B-A3B and gpt-oss only use a few billion "active" parameters per word, so they run 30–60+ tok/s. Dense 70B models are smart but crawl at around 4–6 tok/s.
  2. Bigger context windows use more memory and slow the first token. Use 8–16K unless you're pasting long documents.
  3. Plug in the power brick and use the machine's performance mode for best results.
